# Размещение на VPS, включая Aeza

Тариф и сервер ещё не выбраны, покупка и публичная публикация не выполнялись. Нужны фактические vCPU/RAM/диск, версия Linux, способ SSH-доступа и, для HTTPS, домен. Для старта ориентир — 2 vCPU, 2 ГБ RAM, не менее 5 ГБ свободного диска; OCR и сборка могут потребовать больше. До сравнения характеристик нельзя обещать работу на конкретном тарифе за 2–3 евро.

1. Установить Docker Engine и Compose v2.24+ по официальной инструкции для ОС сервера. Код получить из репозитория, используя обычный доступ владельца.
2. Скопировать `.env.example` в `.env`, ограничить права файла, задать длинный случайный `APP_ACCESS_TOKEN`, адрес шлюза, ключ, модель и тарифы. Не пересылать SSH-пароль, приватный ключ или API-ключ в чат.
3. `docker compose up --build -d`, затем `docker compose exec pulse python -m scripts.smoke`.
4. Импортировать кейс командой из README. Нажать обновление официальных источников. Проверить новую новость и живой ответ модели; доступность сервиса или зелёный healthcheck не заменяет этот шаг.
5. Настроить HTTPS reverse proxy (например, Caddy/Nginx) к `127.0.0.1:8000`. Не открывать порт контейнера наружу напрямую. Общий код защищает весь конкурсный стенд, а не права разных корпоративных клиентов.
6. Проверить полный сценарий с отдельного компьютера и повторить после перезапуска контейнера. Передать жюри адрес, код доступа и инструкции безопасным способом; подтвердить, что шлюз продолжит работать после дедлайна.

Для обновления: получить новую версию кода, собрать образ, `docker compose up -d`. Сначала сделать резервную копию БД через SQLite backup API, а не копированием работающего WAL-файла. Хранить исходные документы и метаданные вместе с БД. Не использовать `docker compose down -v`, если нужно сохранить данные.

Пример резервной копии внутри контейнера:

```bash
docker compose exec pulse python -c "import sqlite3; a=sqlite3.connect('/app/data/alfa.db'); b=sqlite3.connect('/app/data/alfa.backup.db'); a.backup(b); b.close(); a.close()"
```

Работающий процесс и открытые соединения не считаются сохранёнными при переносе среды. Запуск всегда выполняется заново. Для банковской эксплуатации отдельно нужны IAM, TLS/сеть по политике банка, распределённые лимиты, мониторинг, нагрузочные тесты и экспертный процесс контроля контента.
